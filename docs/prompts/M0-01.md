# Task M0-01 — Implement the first real Rust CLI

You are the THRN implementation agent. The lead architect has defined this task. Read `AGENTS.md`, the entire `THRN_PROJECT_SPEC.md` (especially §§0–3, 5–6, 13–14), `docs/DECISIONS.md`, and actual repository files before coding. Inspect rather than assume. You are already on the task's feature branch, selected by `scripts/run-task.sh`.

## Objective

Replace the intentionally temporary `src/main.rs` with a real, maintainable, offline-first Rust command-line foundation. Scope is **only M0-01**. Do not build registries, fetchers, installers, agent adapters, release publishing, or web interfaces in this task.

## Architecture chosen by architect

- Retain one Rust binary crate and `edition = "2024"` with pinned toolchain and lockfile.
- Use maintained, mutually compatible current `clap` 4 derive parsing and `thiserror` for typed domain errors. `anyhow` at the application boundary is optional only if justified. Use std for other functionality.
- Implement a small `cli` module for parser definitions, a `doctor` read-only handler module, and an `error` module only if useful. Avoid empty future modules.
- Use `clap` generated `--help` and `--version`; reserve stable command hierarchy with `doctor` now. Do not advertise nonfunctional skills commands.
- `thrn doctor` exits successfully and explicitly reports only diagnostics actually performed (e.g. binary/version/build platform); no fake registry/agent health checks. Must perform no I/O writes and no network requests.
- Unknown command/subcommand or invalid options: nonzero and actionable stderr, no panic or untrusted input `unwrap`.
- CLI binary name remains `thrn`; no new language runtimes or external services.
- Existing `.github/workflows/ci.yml`, scripts, repo conventions, and license are baseline; modify only to fix an evidenced compatibility bug. Keep changes minimal.

## Acceptance criteria — prove each

1. `cargo run --locked -- --help` prints meaningful THRN description, `doctor` and normal help.
2. `cargo run --locked -- --version` prints `thrn 0.1.0` (or equivalent crate-derived clap value) and exits 0.
3. `cargo run --locked -- doctor` prints truthful read-only diagnostic information and exits 0 offline.
4. An unknown subcommand exits nonzero and produces helpful error text on stderr, without panics.
5. Integration tests launch the actual compiled CLI binary (use `assert_cmd` or standard process APIs) and cover help, version, doctor and invalid command. Tests require no internet, credentials or shared personal directories.
6. `bash scripts/verify.sh` passes (fmt, Clippy warnings-as-errors, tests, release build); `Cargo.lock` reflects resolved dependencies. If a step cannot run, report the real blocker and fail rather than claim success.
7. Update `README.md` with verified usage examples and accurate current status. Do not claim skills installation works.
